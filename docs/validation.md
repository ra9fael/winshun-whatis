# 验证与人工验收

[English](validation.en.md)

日期：2026-11-08。用户实测后确认功能与改版界面合适，并授权建立 GitHub 仓库和 `v0.1.0` 标签。本文件区分用户反馈、自动测试和未覆盖边界。

## 1. 问题是什么

验证 Windows 窗口到 EXE 的读取、Win顺协议/权限/生命周期、原生界面及独立仓库打包。宿主为 Win顺 0.22.0 开发构建（HEAD `1769c368`），Windows x64；用户验收及完整桌面测试对应 GCC 13.2 构建。

## 2. 为什么

路径可能拒绝访问，异步响应可能迟到，选取层会影响命中与输入。合成全局输入的成功返回不能证明物理输入行为。首次准备标签时，新增 MSVC 构建的桌面复验无法完成：`SetCursorPos(248,180)` 返回 0，实际位置没有改变；原先已通过的 GCC 二进制复验也遇到相同环境问题。新增测试前置检查避免把错误鼠标位置误报为插件回归。

## 3. 改了什么

插件实现、状态机及原生卡片见 [实现说明](implementation.md)。本轮补齐 `0.1.0` 双语变更记录、仓库主页、独立 CI、固定版本清单 schema、仅提取当前版本的双语包说明；测试辅助程序显式链接 `advapi32`。产品的查询、权限和交互实现未改动。

自动化仅向自建测试窗口发送定向消息，不写剪贴板、不执行 Explorer 成功动作。测试结束关闭自建进程并尝试恢复鼠标；当前桌面拒绝鼠标移动时原位置也未改变。未结束或修改用户运行中的 Win顺及其他插件。旧轮次未完成清理的开发目录保留；本轮可再生成文件放在忽略的 `build/tag-msvc/`，打包物放在 `dist/tag-v0.1.0/`。

## 5. 没测的

- 用户反馈未细分真实单击/拖动隔离、Esc/焦点/停用、复制及 Explorer 成功路径；自动化不能补足这些证据。
- 真实 100/150/200% 混合 DPI、负坐标副屏、小屏大字号、管理员/UIAccess/UAC 安全桌面、其他会话、受保护或挂起进程、跨进程嵌入、透明窗口自定义命中、屏幕阅读器。
- MSVC 构建的完整桌面集成、100 次长期稳定性、资源及 p50/p95 标定、所有 Windows 版本、代码签名。
- GitHub Release 与插件库收录不属于本次建立仓库和打标签的交付范围。

后续逐项验收时，在本地可交互桌面准备带计数按钮的测试程序，核对选取不触发目标、取消无残留、跨屏命中与缩放正确，再检查剪贴板内容、Explorer 选中目标、键盘/屏幕阅读器和资源曲线。读取普通窗口成功不代表所有进程可读。
