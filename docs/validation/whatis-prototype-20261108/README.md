# “这是什么”交互原型验证

[English](README.en.md)

日期：2026-11-08。范围：方案、独立 HTML 和会话内交互片段。原生插件尚未实现。

## 1. 问题是什么

需要为 Win顺 新插件“这是什么”确认“选取窗口 → 查看 EXE → 复制 / 定位”的交互，并展示普通窗口、陌生弹窗、宿主窗口和路径不可读四类结果。需在桌面与窄屏可操作，不能把模拟数据冒充真实系统查询。

环境：Windows；Playwright 控制独立 headless Microsoft Edge `156.0.4314.58`。本地主仓库 HEAD：`1769c368`。未启动或修改用户的 Win顺 实例。

## 2. 为什么

窗口与应用不总是一对一；路径查询也可能失败。原型需要区分未选取、预览、锁定、部分信息，以及宿主归属尚未确认，而不是只展示一张成功结果截图。

选取状态还必须处理取消与迟到输入：按住准星拖动时按 Esc 后，后续松开鼠标不能提交一个已取消的选择。切换样例时必须关闭属于上一次结果的操作预览。

## 5. 没测的

- 真实 Windows 窗口枚举、HWND/PID/EXE 查询和原生输入捕获。
- 管理员 / 受保护进程、跨会话、安全桌面、宿主内容进程和物理多屏混合 DPI。
- 原生性能、内存、句柄泄漏、插件安装以及 Win顺 真宿主往返。
- 实际系统剪贴板写入、真实资源管理器定位、物理触屏和屏幕阅读器。
- 会话宿主的交互状态持久化与 Tweak 控件没有进行产品内实测；独立与沙箱环境均验证了无宿主 API 的正常降级。

这些未测项不影响 HTML 作为交互原型，但不能据此声称原生插件可用。
