# “这是什么”界面更新验证

[English](README.en.md)

## 1. 问题是什么

用户确认原版功能可用，但认为界面丑陋。旧版同时显示系统标题栏和内部标题，字段分散，路径是大块原生编辑框，次要信息与主操作争夺视觉注意。日期：2026-11-08；Windows x64、GCC 13.2、Win顺 0.22.0 开发宿主。

## 2. 为什么

之前优先接通 Win32 能力和宿主协议，原生 UI 只作线性摆放，未落实原型的信息层级；文字、控件和留白缺乏一致尺寸，按钮没有悬停反馈，空态仍显示无效字段。

## 3. 改了什么

`ra9fael.whatis/src/ui/window.*` 重排为 480 × 388 的默认结果卡：自定义可拖动标题栏、关闭按钮、通用程序图形、EXE 主标题、PID/状态、窗口标题、独立路径容器、并列复制/定位操作，以及底部详情/重新选取。普通归属说明进入折叠详情，异常说明保持直接可见，空态只显示说明和选取入口。

使用 GDI+ 抗锯齿图形，保留原生按钮与可选择文字的键盘语义，提供悬停/焦点状态，中英文分别选择微软雅黑 UI / Segoe UI。沿用宿主颜色、圆角和字号。没有更改权限、窗口查询、选取状态机或主程序源码。构建新增 Windows 系统 `gdiplus.dll` 依赖。

测试脚本修正两点：拖动步骤改用有超时的同步定向消息，避免异步消息与鼠标移动之间的时序竞争；宿主脚本将 `--out` 等路径转为绝对路径，避免改变 cwd 后把预览输出写到错误位置。

## 5. 没测的

实际鼠标拖动标题栏、Windows 10/11 各版本的 DWM 阴影和圆角、真实跨屏混合 DPI、高对比度及屏幕阅读器仍需人工验收。模拟 DPI 消息只证明布局响应，不证明多屏选取精度。物理点击隔离、剪贴板和 Explorer 成功动作沿用前轮未验收状态；用户“功能上没问题”的反馈没有替代这些具体测试记录。核心/平台逻辑未改，沿用前轮 CTest 2/2，未重复运行。归档 UI 导入及正式发布未执行。
