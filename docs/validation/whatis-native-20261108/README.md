# 验证与人工验收

[English](README.en.md)

日期：2026-11-08。开发预览尚不具备正式发布条件。精选机器可读证据保存在工作台主仓库 `WinShun/docs/validation/whatis-native-20261108/`。

## 1. 问题是什么

需验证从真实 Windows 窗口读取 EXE 的能力，以及在真实 Win顺宿主中的协议、权限、生命周期和原生交互。HTML 原型测试不能替代原生测试。环境为 Windows x64、GCC 13.2、Win顺 0.22.0 开发构建，主仓库 HEAD `1769c368`。

## 2. 为什么

窗口所属进程可能无法读取，异步结果可能迟到，宿主调用不能阻塞协议线程；选取层也会影响命中与输入。当前桌面的合成输入 API 返回成功，但独立测试按钮没有收到点击，因此不采用合成全局输入的返回值判断物理交互成功。

## 3. 改了什么

增加独立 `ra9fael.whatis` 插件、有限权限查询、会话状态机、临时输入层、原生卡片、异步宿主工具、测试与开发打包。未修改主程序代码。完整架构和相对原型的偏差见 [实现说明](../../../../ra9fael.whatis/docs/implementation.md)。

## 5. 没测的

- **L4 发布阻塞**：真实鼠标单击/拖动是否阻断目标按钮，键盘 Esc、焦点转移、停用时是否恢复输入；真实剪贴板及 Explorer 成功动作。
- **L4 发布阻塞**：100/150/200% 混合 DPI、多屏负坐标、小屏大字号、管理员/UIAccess、UAC 安全桌面、其他会话、受保护进程、挂起窗口、跨进程嵌入、自定义透明命中、屏幕阅读器。
- **L5 未做**：100 次长时间稳定性、资源与 p50/p95 性能标定、不同 Windows 系统版本、MSVC 编译、签名、仓库 CI、公开 Release 与插件索引。
- 普通自动化窗口读取成功不能推断所有进程可读；12 次句柄检查不能代替长期稳定性；命中测试不能证明物理点击隔离。

### 发布前手工步骤

在可本地操作的测试桌面上安装开发包。准备含点击计数按钮的测试窗口、普通应用及管理员应用；分别单击选取和拖动选取，确认结果正确且目标计数不增加。Esc、切走焦点、锁屏/解锁、停用插件后检查没有残留输入层。对不可查询进程核对 PID 与错误码。

在 100/150/200% 混合缩放屏幕及负坐标副屏重复，确认边框、命中、提示与按钮完整可达；再手动复制非敏感路径并核对，定位测试 EXE，确认 Explorer 只选中文件。记录屏幕阅读器、键盘导航、连续 100 次选取的内存/句柄及延迟。发现问题后修复并重新验证，再考虑发布。
